## 条目 1:macOS 焦点窗选区 AX 真机回环(挂起)

**条目来源**:`todo.md:72`(patrol-20261014-T1:「macOS AX 真机回环…维持挂起(需真机授权会话)」)+ `docs` 相关(F13b macOS 焦点窗选区实装,`patrol-20261014-S1/S2`)。

**背景(教学性)**:F13b 让 macOS 取词热键读焦点窗口的选区文字。实现走 AX API,已落地;但 macOS 的辅助功能权限(TCC)必须由**真实用户会话**在系统设置里手动授权,且授权后要在**真机**上验证「能读到选中文字」。CI 只能验证到「跳过分支」——macOS runner 上 AX 读不到焦点元素,回环断言不成立,故用 QSKIP 诚实跳过。结论:**CI 验不了,必须真机授权会话**。

**推荐决策**:维持挂起,待用户提供真机授权会话验证。**需用户输入,暂缓**——解锁条件 = 用户在有辅助功能授权且真实登录会话的 macOS 真机上跑一次回环(选中一段文字 → 按取词热键 → 确认读到选区并弹窗)。在此之前,取词走剪贴板兜底(既有 P-5 路径)不受影响。

**理由**:
- **成本**:零(纯等待,不动代码;本机无 macOS 真机,无法代验)。
- **收益**:真机回环通过后,F13b 从「CI 跳过分支」升级为「真机已验证」,取词热键在 macOS 上获得确定性证据。
- **风险**:继续挂起 = macOS 取词热键缺少真机验证证据,但功能已实现且剪贴板兜底可用,不阻塞主链路;伪造验证证据违反诚实审计口径(不装)。

**立即执行动作**:无。**不做/延后**:不伪造真机结果、不降级为「仅剪贴板」注销 F13b(功能已在,只差验证证据)。
**需用户输入,暂缓**:macOS 真机授权会话回环(用户操作)。
**exec-actions 跳过标记(2026-10-30)**:「待用户:macOS 真机授权会话回环」——本批无可执行动作,维持挂起。

## 条目 2:LLM provider 集成(挂起)

**条目来源**:`todo.md:72`(「LLM provider 集成维持挂起…需真实凭据+计费口径」)+ `docs/roadmap.md:98-104`(AI Integration · LLM integration,复核 PATROL1016「解锁条件不变——凭据与计费口径仍未到位,维持挂起」)。

**背景(教学性)**:P-9 已把 AI Provider 做成抽象接口(`AiProvider` 接口 + `CommandAiProvider` 外部命令桥 + `HeuristicAiProvider` 启发式兜底),本地/CLI 的 AI 用法(翻译、语法、造句)已覆盖。**LLM provider 集成**指的是接一个真正的在线大模型服务(provider auth / streaming / caching / prompts)——它需要**外部服务凭据**(账号/API key)和**计费口径**(谁付钱、额度怎么管)。这两样都是用户私有数据/财务决策,不是工程能代决的。

**推荐决策**:维持挂起。解锁条件 = 用户给出可用 provider 凭据并明确计费口径。**需用户输入,暂缓**——在凭据与计费到位前,不接任何真实 LLM 服务;本地 AI 面继续走外部命令桥(P-9 已覆盖)。

**理由**:
- **成本**:零(等待凭据,不动代码)。
- **收益**:解锁后 AI 质量从「本地桥 + 启发式」升级为「真 LLM」,但这是用户付费换体验,须用户点头。
- **风险**:无凭据硬接 = 需要用户私有密钥(违反「凭据不进仓、不代决」口径)+ 产生真实费用(计费未定,风险外溢)。

**立即执行动作**:无。**不做/延后**:不接任何真实 LLM 服务、不引入 provider 凭据、不做计费决策(均属用户私有/财务面)。
**需用户输入,暂缓**:provider 凭据(用户提供)+ 计费口径(用户明确)。
**exec-actions 跳过标记(2026-10-30)**:「待用户:LLM provider 凭据 + 计费口径」——本批无可执行动作,维持挂起。
